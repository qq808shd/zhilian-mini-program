# V4 学习闭环

## 现状审计（2026-09-06）

原学习进度是分组最远浏览位置，不能证明回忆或掌握；续学始终指向最后位置，完成组仍停在末条。答题事件已具备离线队列和服务端幂等，须保留。旧错题连续两次正确即可退出，没有日期间隔，也没有自评来源。学习、练习和复习依靠用户重新选择分类衔接；搜索本身不写进度，应继续保持。云端只支持统计和浏览进度，新增连续性数据需要扩展客户端和服务端协议。

## 数据与兼容

新增独立 V4 学习状态及事件队列，旧题库、稳定 ID、统计、迁移和分组均不改变。知识记录包含正式学习时间、自评、复习阶段、下次日期、连续正确及错误次数。旧浏览前缀只迁移为已学习／待检验，旧 activeWrong 迁移为待复习；旧聚合统计不伪造成近七日事件。

北京时间自然日作为任务和间隔的统一时区。答错／不会降到阶段 0；正确安排次日，按到期跨日正确依次安排 3 天、7 天，再基本掌握。同日正确不会跨越阶段。模糊安排次日；记住了只是自评，仍须检验。搜索不触发正式学习事件。

今日计划首次生成后冻结：最多 10 项到期复习、10 条新学、5 道对应练习；本轮错误追加最多 10 项再练，每个知识只补一次，仍错安排次日。当天不无限加量，次日重新按到期和剩余内容生成。任务完成与学习状态以同一事件保存；未确认选项等 UI 草稿仅留本机。

新增云事件按用户与事件 ID 去重，并按发生时间重放；跨设备同日以最早计划为主，其他离线计划已完成任务并入记录，但不会增加主计划任务量。同步保留本机未确认事件；旧服务器不支持 V4 时不丢弃新队列，明确提示需要更新服务端。

## 页面与验证

首页唯一主要操作为今日学习；自由分类、目录查询和测验继续开放。正式学习完成后直接开始本组少量巩固；复习按待复习／巩固中／已掌握展示；测验结果直接连接本轮错题。我的展示掌握、今日完成、待巩固及真实七日正确率。

本文件在交付时补充实际测试及微信开发者工具验证结果。开发前 GitHub 拉取返回 Empty reply from server，按任务要求继续本地开发。


## 最终实现

- `learningModel.js` 是无微信依赖的纯状态算法，客户端和 Node 服务端复用。`learningEngine.js` 负责本地迁移、每日任务、统一动作与概览、自评及同步队列。
- 知识状态支持未学习、学习中、已学习／待检验、待复习、巩固中、已掌握。状态由真实记录和当前日期推导，不用浏览百分比猜测。
- 保留原统计键与旧迁移；新增答题写入日志，在进程中断后补全计数和队列写入。每日完成事件与学习结果一次保存，重复确认不会重复推进或计数。
- 原有统计仍按唯一事件同步；新学习事件按用户隔离、明确确认、离线保留。其他设备同日相同任务已完成时合并，不重复要求完成；不同任务的学习行为也保留。
- 近七日成绩只取有日期的新作答；今日总结分别统计新学、到期复习、练习、正确率、新掌握、仍需巩固和截至明日到期项。
- 主要变更页面：首页、模块概览、分类分组、正式学习、今日学习与总结、目录查询、知识详情、练习／测验及结果、复习各层、学习记录、我的、帮助与同步说明。
- 隐私草稿补充自评、复习日期和任务信息，版本更新为 `2026-09-06-v4-draft`。旧同意记录需重新确认当前版本才恢复后台同步；本地学习不受影响，没有额外同步开关。
