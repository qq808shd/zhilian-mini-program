# 知练 UI / UX 重构说明

日期：2026-09-05

内容：言语模块、数量关系、资料分析、常识理论。共 14 个分类，1044 条知识、1089 道题。无独立刷题页、收藏、用户中心、AI、整套模拟考试、计时试卷规则或每日任务数据。

## 主要问题与决策

1. 原首页只回答选哪个模块。新的主卡回答下一步做什么：有记录则续学，无记录则从原有高频成语开始。
2. 原分组进度仅记录最远位置，打开总从第一条开始。增加独立的本机阅读位置，不改变云端最远进度模型。旧记录按最远浏览位置续接。
3. 原学习完成只提供重新学习/返回。新入口把本组知识对应的题目送往练习准备页。
4. 原练习与考试没有区别。复用一个题库与页面，引入逐题确认的专项练习、统一交卷的专项测验；不虚构整套模拟卷或倒计时。
5. 原结果将所有解析铺成很长的页面。现在先给本次反馈和行动，再逐题阅读，可只看错题。
6. 原复习只有高频知识摘要。现在保留前 5 个错点，并支持实际错题逐题复习、再次练习、查看巩固状态。
7. 原部分子页面仅 onLoad 读取统计。改为 onShow 刷新，返回后反映最新状态。
8. 原详情的详细解析一直可见。与回忆卡的展开状态统一，避免“先回忆”形同虚设。

## 信息架构与闭环

三个 Tab：学习 / 练习 / 复习。保留 10 条已有页面路由。

- 学习：继续上次 → 模块 → 分类 → 分组 → 回忆/解析 → 本组练习。
- 练习：模块 → 分类 → 方式与题量 → 答题 → 确认/交卷 → 本次反馈 → 逐题解析。
- 复习：优先巩固 → 分类 → 高频错点与具体错题 → 知识点 → 关联练习 → 连续答对两次移出待复习。
- 反馈：本次错误所在分类 → 重练本次错题 / 继续专项学习 / 分类复习记录。

没有每日强制目标、虚构连续学习天数或成绩趋势。累计正确率只在存在作答时计算；已浏览知识不等于已掌握。浏览解析不改变错题状态。

## 设计与素材

在现有 design-system/default/MASTER.md 上升级为 Quiet Growth。暖白、灰绿、低饱和绿色，白色内容卡片，轻边框，有限圆角。中文系统字体，正文字号与对比度优先。

保留并重新着色原有线性 TabBar SVG，生成原生 TabBar 所需 PNG。中文单字用于科目文字标识。此版本不引入新插画：续学卡、空状态和结果页依靠排版即可清晰表达，Image 2 无需调用。

公共能力：ui-entry（模块/分类列表）、progress-meter（进度）、ui-state（空状态/恢复）、math-formula（原有数学结构）。按钮、卡片、排版、状态与间距使用全局样式，原生组件颜色仅在桥接位置定义。

## 数据与接口边界

- 题库文件、稳定 ID、分组边界和排序不变。
- 不修改 storage.js、cloudSync.js、生产开关或服务端。
- 阅读位置另存本机键 zhilian_reading_positions_v1，不替代云端学习进度。
- 专项练习在确认答案时写入原有统计/事件；交卷跳过已记录题目，避免重复计数。
- 专项测验仅在交卷时写入；未答题交卷前明确确认，按原口径计错。
- 每次最多 20 题。大词库和大错题列表每批渲染 40 条。
- 用时只计页面可见期间，不是倒计时；本次测验草稿不新增跨重启或跨设备保存能力。
- 学习和复习数据为本地优先，网络失败继续沿用既有自动同步机制。

## 验证范围

Validation: L3，原因是本次涉及跨页导航、公共 UI 和答题确认时机。

定向测试：题量 0/1–10/11–20/21–100/100+，精确续学与云端最远位置不倒退，本组题目关联，确认/交卷去重，测验改答案与未答提交，连续两次正确巩固，大错题分页，搜索清空恢复，非法学习路由恢复。复用 storage-sync 测试检查事件与进度规则。

微信开发者工具负责实际小屏布局、展开、滚动、导航与答案页视觉；不通过测试清空真实用户数据。静态检查为所有小程序 JS 语法检查和 diff 空白检查。不进行无关服务端回归或发布部署。

- 学习体验与存储同步定向测试共 10 项通过；修正交卷弹窗的确认文案长度后，相关 8 项再次通过。
