## 1. 项目定位与范围

- 产品名：**知练**。
- 形态：原生微信小程序，当前 AppID 为 `wx01e13d3df486356c`。
- 用户：当前由本人及身边朋友使用，内容聚焦公考等需要记忆和客观题训练的知识。
- 核心流程：**选择学习范围 → 分别进入新学或到期复习 → 标记学习程度并继续 → 系统安排下次复习**；学习进度与程度独立，分类自由学习、自由练习与专项测验继续保留。现行规则见 [V5 学习与复习](v5-learning.md)。
- 学习小组 V1 是独立的邀请制学习契约：全部手动记录，不读取知练学习/答题行为；不做社区、聊天、评论、关注、排行榜或公开小组广场，不强制原有学习用户参加。详见 [学习小组 V1](study-groups/README.md)。
- 内容可重复学习，已完成一组不代表该组被锁定。
- GitHub 用于保存代码、整理后的学习资料和项目说明；它不是线上数据库，也不会自动保存 Codex 的完整对话上下文。本文件是跨电脑延续项目约束的主要入口。

## 2. 当前运行和架构基线

- 项目根目录直接导入微信开发者工具，`miniprogramRoot` 为 `miniprogram/`。
- 采用“**题库本地 + 用户数据云端 + 本地优先同步**”架构：学习资料仍随小程序打包，学习进度、答题统计和错题状态先写微信本地存储，再批量同步云端。
- 云端保存独立的小组、契约、手动记录及事件，并保存微信用户标识、学习分类与每日数量设置、学习进度、自评、掌握与复习状态、复习日期、今日任务、答题统计、错题状态和同步元数据；不搬迁 888 条成语等静态题库。
- 小程序通过 `wx.login` 获取一次性 code；服务端用 AppID、AppSecret 换取 OpenID，并返回自己的签名会话。不得自建用户名/密码，不收集手机号；昵称头像可由用户通过微信原生控件主动选择，仅保存在本机用于展示，不上传服务端。
- 自建服务端位于 `server/`：Node.js 24、内置 HTTP/加密/SQLite，无第三方运行依赖，默认监听 `127.0.0.1:8787`，由 Nginx 提供公网 HTTPS。
- 当前生产环境为阿里云北京地域轻量应用服务器（Ubuntu 24.04），已通过本机 SSH 固定别名 `zhilian-aliyun` 接入。知练部署目录为 `/opt/zhilian-mini-program`，运行用户为 `zhilian`，数据库目录为 `/var/lib/zhilian-api`；使用项目内隔离 Node.js 24.19，不替换系统 Node。Nginx 与 `zhilian-api` 已启用并运行，公网入口为 `https://api.dabaommz.cloud`。
- 服务端同步按唯一答题事件幂等处理，网络重试不重复累计；首次连接时把已有本机记录作为基线导入。
- 云端不可用时不能阻断学习；待同步事件必须持久保留在本地，恢复网络后自动重试。
- **生产连接已启用**：`miniprogram/config/cloud.js` 中 `enabled: true`，`baseUrl` 为 `https://api.dabaommz.cloud`。域名已备案并配置 HTTPS，且已加入微信 `request` 合法域名。
- 当前阿里云个人测试证书有效期截至 2026-12-01 23:59:59 UTC（北京时间 2026-12-02 07:59:59），到期前必须重新申请、替换证书并平滑重载 Nginx。
- 不使用 `wx.cloud`。启用后由 `wx.request` 访问自建阿里云服务器。
- AppSecret、`SESSION_SECRET`、生产 `.env`、SQLite 数据库和备份只能存在服务器，禁止进入小程序代码或 GitHub。
- 打包必须包含 `miniprogram/assets` 的界面图片和 Tab 图标；不能在 `packOptions.ignore` 中忽略 `assets` 目录。
- `project.private.config.json` 是每台电脑的私有配置，已被 `.gitignore` 忽略；换电脑后由微信开发者工具重新生成。
- 仓库根目录 `package.json` 仅提供 Node 内置测试入口，`npm test` 运行小程序与服务端测试，无需安装依赖；`server/package.json` 保留独立服务端入口。

## 3. 信息架构和核心功能

### 3.1 学习

- 学习范围按模块、分类选择；自由学习保留“模块 → 分类 → 分组”入口，不把所有内容铺成长列表。
- 当前模块包括：言语模块、数量关系、资料分析、常识理论。分类继续按模块细分，例如言语下的成语、三字词、诗词、关联词、实词及资料分析下的增长率、增长量、比重等。
- 常规大题库每组最多 20 条，分组是阅读组织方式，保留来源批次、资料顺序和稳定 ID；允许随时回看、重学。
- 单条学习采用占主要屏幕空间的大卡片。新学先显示标题，点击查看后才展示原有释义、解析、记忆提示和公式，未揭示也可直接标记学习程度；底部固定“陌生／了解／掌握”，点击任一项保存后自动进入下一条，不再用“下一条”隐式完成。
- 首次点击任意程度都记为已学习；“已学习＋陌生”与默认“陌生＋未学习”区分。修改程度、重复学习不重复增加已学习数量，时间推移不减少已学习进度。标签体现用户判断，到期日期决定复习安排。
- “熟知”通过卡片星标直接打开居中确定／取消弹窗，表示已学习并退出自动复习；允许取消熟知、保留此前学习记录并恢复复习。熟知不表示永远不会遗忘。
- 支持的分类提供全部查看与搜索，可按标题和释义查找；大词库每次渐进加载 40 条。单纯滑动、回看、目录查询及详情展开不算学习，详情页主动评分才改变学习记录。
- V6 首页依次为轻量学习范围、一个今日主行动、已学习进度和程度摘要。到期复习优先，其次剩余新学；另一任务降级为状态行与辅助入口。全部完成后只提供可选练习，不追加任务。自由学习、规则与设置继续可达，底层仍为 V5。
- 学习设置继承首页当前范围，不再选择模块、分类或来源批次；数量卡使用原生滑动条和精确加减。数量为整数 `1..min(200, 分类知识总量)`，分类不超过 200 时最右端表示全部，默认成语 10 个。新学按全分类既有顺序安排，不足时按实际剩余量，不跨分类补齐。
- 保存分类或数量后立即生效，保留当天已完成记录；各分类当日已新学数量抵扣对应目标。新学与复习分别按北京时间日期、模式和分类保存会话，切换后可返回对应进度。自由学习不擅自改变当前设置。
- 本组学完后可继续下一组或主动自由练习，不自动跳入 5 道配套题。自由练习与专项测验保留既有最多 20 题限制。
- 学习设置中的“清空学习记录”只作用于首页当前范围，弹窗写明名称，确认后重置已学、程度（含熟知）、复习安排、当天会话和阅读位置；保留其他范围、数量偏好和答题统计。取消不改变数据。
- 本机阅读位置独立保存，原分组最远浏览进度保留为辅助兼容数据，不能代替本次正式学习标记。

### 3.2 考试

- Tab 为“学习 / 练习 / 小组 / 我的”，复习由学习首页进入。练习页复用原考试路由：先推荐有效当前错题，其次当前范围已学知识的真实关联题；无记录时引导自由专项。原模块、分类、组卷、巩固练习（确认后逐题解析）和专项测验（交卷后统一解析）保持可达，不是整套模拟卷。
- 结果页只在本次作答实际改变已学且未免复习知识的调度证据时显示更新数量；不能用统一成功文案冒充更新，也不把作答结果改成主动学习程度。
- 提供答题卡、标记和实际前台用时；所有入口每次最多 20 题，不设虚构考试时限。
- 专项练习确认时计入原有答题事件，最终提交跳过已记录题目；测验统一交卷计入。结果给出错题再练与专项学习建议。
- 大题库提供 10 题或 20 题选项；不要提供一次考完 888 道等超大组卷选项。
- 题目答错后记录题目、答题次数、错误次数、正确率/错误率和当前错题状态。
- 正常考试与复习中的错题专项考试是两个入口，但使用同一套统计口径。
- 错题专项考试随机抽取最多 20 题，不能把全部错题一次性传入页面和逐题同步写入本地存储，以免大错题集造成卡顿。

### 3.3 复习

- 自动复习针对当前范围的已学习知识逐条安排，陌生、了解和掌握都参与；未学习内容进入新学，熟知退出自动复习。
- 每条知识根据记忆稳定性、难度、上次学习时间与历次反馈计算到期日期。当前采用 FSRS-6 公开默认参数和 90% 目标回忆概率，尚未针对个人进行参数拟合；不能把结果描述为个人遗忘率的精确测量。
- 陌生、了解、掌握在调度中分别采用 Again、Hard、Good 反馈。在其他条件相近时，较弱的程度通常更早复习；同一程度的不同知识也可能有不同日期。熟知是独立免复习操作，不是 FSRS Easy。
- 复习先尝试回忆，再查看内容并选择三种程度；保存后自动继续，算法更新下次日期。当天完成新学或复习后当天不再自动重复安排，间隔按北京时间自然日取整且至少 1 天；这不表示当天遗忘率为零。
- 新学与复习独立进入，不再采用固定 1／3／7 天阶段或必经配套题、再练链；当前分类已到期项均可参与，不再固定最多 10 个。显示实际待复习数量和下次日期，标签不会因到期而自动降级。
- 复习记录仍支持按分类和学习程度查找、回看、修改标记，长列表继续渐进加载。主动错题练习、关联题和专项测验保留其答题记录，最多 20 题；题目统计不能替代正式已学习标记或用户明确的熟知选择。

### 4.1 成语词库的来源和先后顺序

成语是增量合并，不是后一次资料替换前一次资料：

1. **原有高频词库 153 条必须排在最前面**。它包含 Excel 中的 100 条以及更早资料中去重后保留的成语。
2. `成语800词.zip` 图片资料实际有编号 1—839：
   - 排除 4 个非四字词：`海水不可斗量`、`百思不得其解`、`夏虫不可语冰`、`可望而不可即`；
   - 图片资料内部有 1 个重复标题 `老生常谈`；
   - 与原有词库重合 99 条；
   - 去重后净新增 735 条，排在原有 153 条之后。
3. 图片增量必须保持照片编号升序；去重时保留原有版本，不能覆盖原有释义、ID、顺序和历史统计。
4. 现行严格分组不能跨资料批次混合：
   - 第 1—7 组：每组 20 条原有高频词；

### 4.3 特殊内容建模

- 三字词是言语模块中的独立“三字词”分类，不并入四字成语。
- 关联词不能按“因此”“但是”等单个词逐张学习。应按因果、转折、递进、并列、条件、假设等**逻辑关系**建卡，一张卡学习该关系常见的多个关联标志及辨析。
- 资料分析当前分类：增长率、增长量、比重、平均数、倍数与比值、混合增长、贡献与拉动。
- 数学公式必须使用真实的分子/分母和分数线排版，不能把分式按普通文字顺序挤在一行。每张公式卡尽量包含基础定义、变形或推导过程、适用条件和易错点。

## 10. 对话决策摘要

以下是截至 2026-09-03 已确认、会影响后续实现的主要决定：

1. 小程序以个人背诵和客观题训练为主，核心是能学、能考、能定位高频错题。
2. 学习内容先按模块和分类进入，再按每组约 20 条学习；学习主体是一张可滑动的大卡。
3. 考试按分类随机抽题，错误需要累计统计；复习页先看分类表现，再进入查看具体高频错题并专项再考。
4. 全部层级保持统一视觉与足够内容宽度；2026-09-05 起采用淡绿色 Quiet Growth，首页按主次安排卡片与轻入口。
5. 成语、三字词和实词先隐藏释义，点击查看解析后展示。
6. 关联词改为按逻辑关系学习一组标志词，不按单个词机械背诵。
7. 新增资料分析模块，公式要有推导，并用真正的分数线结构显示。
8. 成语和三字词支持“全部查看与搜索”；大词库使用渐进加载。
9. 用户提供的新资料默认视为增量。后传的 800 词图片不能替换前面的原有成语。
10. 成语学习顺序按资料优先级固定：原有 153 条高频词在前，图片净新增 735 条在后，而且分组不得跨批次混合。
11. 为支持本人和身边朋友使用，采用阿里云北京地域轻量应用服务器同步用户学习数据；题库继续留在小程序，不让低配服务器承担静态资料请求。
12. 云同步坚持本地优先、离线可用、批量上传和事件幂等；不因服务器故障中断学习。
13. 用户身份使用微信 OpenID，不建设密码账号体系，不收集非必要个人资料。
14. GitHub 只保存项目文件，不自动保存聊天记忆；因此用本文件维护可审查、可版本化的长期上下文。
15. 2026-09-03 起改用新注册的小程序 AppID `wx01e13d3df486356c`；旧 AppID 下的本地学习记录无需迁移，新小程序按全新用户数据空间启用。
