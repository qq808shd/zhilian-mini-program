# 知练「我的」与首次使用设计方案

日期：2026-09-05。阶段：已实现为原生小程序页面与交互；主体资料及真实设备验证待补齐。

用户已确认备案号、运营主体、联系邮箱暂留空，后续统一提供。所有相关文字均为明确的设计占位，不填写仿真的备案号，也不把此方案当作可直接发布的协议。

- 页面范围：首次欢迎、我的、设置、关于知练。个人资料编辑、同步详情、协议阅读和帮助作为下级页面按本方案落地。

## 一、导航与页面职责

底部四个 Tab：**学习 / 练习 / 复习 / 我的**。新增“我的”放在最后，不改变前三项顺序和已有学习路径。

| 页面 | 内容 | 操作结果 |
| --- | --- | --- |
| 我的 | 头像、昵称、学习概览、真实同步状态、学习记录、设置、帮助与反馈、关于、备案入口 | 进入明确的下级页面 |
| 个人资料 | 默认头像或已选头像、昵称输入、保存 | 用户主动选择并保存；取消不修改现有资料 |
| 学习记录 | 最近学习分组、已浏览概览、继续学习 | 复用现有精确续学位置，不能宣称已浏览即掌握 |
| 设置 | 个人资料、学习数据同步、隐私政策、用户协议、微信隐私授权、数据管理 | 展示真实能力，不放无作用开关 |
| 同步详情 | 自动保存说明、本机待同步数量、上次成功时间、失败重试 | 正常时只显示状态，不提供独立同步开关 |
| 关于知练 | 品牌、用途、实际版本、主体、备案号、查询、协议、联系 | 备案与联系资料配置后可查询、复制或联系 |
| 帮助与反馈 | 常见问题、联系渠道 | 说明离线、同步、错题两次巩固、资料删除；联系信息缺失时显示待补齐，不能假装反馈已发送 |
| 协议阅读 | 用户协议、隐私政策，独立标题、版本、生效日期、正文 | 同意前可以完整阅读并返回；可从设置长期查阅 |

“我的”不展示原始 OpenID、登录令牌或 Session Key。也不新增手机号、会员、积分、连续打卡、排行榜、广告、清理缓存等无关功能。

## 二、首次进入与再次打开

微信自己的启动加载界面由平台控制。这里设计的是内容加载后的小程序首次欢迎页，不把它宣称为能替换平台启动画面。

1. 首次使用展示一页欢迎，简述“分类学习 → 专项练习 → 错题巩固”。不做多页教程、广告或倒计时。
2. 用户协议与隐私政策均可先打开阅读；阅读返回保留当前操作状态。
3. 同意框默认未勾选。“同意并开始”未勾选时不可提交，不能预先记录同意。
4. 同意后保存协议版本、同意时间和首次引导完成状态，即自动触发微信登录和后台学习数据同步，无需另行开启；提供可跳过的头像昵称卡后进入学习首页。
5. “暂不同意，仅本机学习”直接进入本地学习，不调用云端登录、上传统计或后台同步；此选择也完成首次引导，避免下次反复骚扰。
6. 本机模式用户以后可点击“我的”中的同步状态卡，再选择“阅读协议并继续”，确认后默认自动同步；无需单独选择同步开关。拒绝可返回，学习不受阻断。
7. 普通再次打开直接进入学习，不重复开屏。涉及新增处理目的或信息范围的协议更新，需要解释变更并重新确认；不要只换版本号后静默继续新增处理。
8. 已有安装用户不能被伪造为“已同意”。升级时如没有有效同意记录，先提供说明与选择，保留已有本机进度及待同步事件。
9. 备案及主体尚未补齐期间，这只是开发预览方案；不能用占位协议记录具有上线效力的同意。

## 三、身份、昵称与头像

现有代码已经在服务端通过 `wx.login` 返回的 code 换取 OpenID，并使用自签会话同步学习数据。无需重新设计微信身份系统，也不需要用户提供微信号。

OpenID 用来区分同一小程序中的用户；它不会自动提供姓名、头像。资料编辑采用用户主动选择头像及填写昵称的方式：`button open-type="chooseAvatar"`、`input type="nickname"`。不使用旧接口强制读取微信资料，不要求填真实姓名。

- 默认显示统一头像与“知练同学”。不填头像昵称也能学习和同步。
- 首次开始后提供一张可跳过的轻量资料卡，优先引导使用微信已有头像和昵称，无需用户先去设置页，也不要求重新上传或手打。点击头像使用微信选择能力，点击昵称使用微信昵称快速填写能力；用户保存后直接用于“我的”，以后仍可修改。
- 这张资料卡不是旧版一次授权就自动取得两项真实资料的接口。头像、昵称分别由用户操作确认，不预先填入尚未获得的数据；跳过则使用默认头像和“知练同学”，不阻断学习。
- 头像选择取消、隐私接口拒绝、文件保存失败都保留原头像；保存失败提示重试。
- 昵称去除首尾空格并限定长度；空白时可保留默认名称，禁止保存后看似成功但丢失。
- 头像选择返回的临时路径不能直接当永久资料使用，需要持久化后再保存引用。
- 第一版头像昵称仅用于本机展示，编辑页明确说明“头像和昵称仅保存在此设备”；学习数据同步继续沿用现有服务端机制。如果后续希望资料也跨设备同步，再加入独立的资料接口和头像存储、校验及删除流程，不能静默扩展收集范围。
- 删除个人资料只清除本机头像和昵称并恢复默认，不删除学习进度或云端学习记录。按钮和确认文案必须写清这个范围。

## 四、同步状态与数据管理闭环

同意协议后自动同步。后台使用现有的本地优先、事件幂等与失败重试能力，不让用户自行管理同步开关。

| 状态 | 用户看到的说明 | 可用操作 |
| --- | --- | --- |
| 尚未同意 | 学习记录暂存此设备 | 阅读协议并继续，同意后自动同步 |
| 同步中 | 正在自动保存，学习可继续 | 查看状态 |
| 最近成功 | 上次同步成功时间 | 查看同步范围，无需操作 |
| 暂时失败 | 本机记录已保留，恢复网络后重试 | 自动重试，也可手动重试 |

旧版用户明确停止过同步的偏好不静默覆盖，需重新确认协议再恢复。底层取消与旧请求结果隔离能力保留，界面移除开启/停止开关。没有有效同意时仍然不登录、不上传；待同步队列始终保留。只有真实请求完成并处理待上传记录后才显示成功。

“清空答题记录”统一在设置管理，复用原有云端重置信号，只清作答统计与错题，保留学习进度；确认弹窗取消不修改数据。“删除本机个人资料”只清此设备的头像昵称，不冒充账号注销或删除云端记录。云端全部数据删除及撤回同意的受理渠道仍待补齐对外联系信息。

## 五、关于、备案与协议

备案号在“我的”有可见入口，并在“关于”完整展示；小程序备案号不能用 API 域名的网站备案号直接替代。备案查询需按微信实际允许的跳转方式接入并验收；不能仅实现复制网址就宣称已经满足链接展示要求。

待补齐字段集中管理：正式产品名称、运营主体、联系邮箱、小程序备案号、协议版本与生效日期。真实版本读取小程序发布信息，开发版明确标注开发版。

协议文案须和实际处理一致，至少覆盖：运营与联系主体、学习服务范围、OpenID 与学习统计/进度处理目的、本机头像昵称、服务器存放位置、保存与删除方式、用户权利及联系渠道、第三方/微信平台处理边界、条款变更机制。未实现的跨设备头像保存、自动注销或删除时限不能写成已有承诺。

自有隐私政策页面不能替代微信后台的《小程序用户隐私保护指引》配置。涉及平台隐私接口时，还要接入微信的隐私授权机制；自有协议确认、微信隐私接口授权、选填头像昵称是不同的动作，不能互相冒充。

## 六、实现范围与验收

已新增页面：welcome、me、profile、settings、sync-status、about、legal、help、history 和受业务域名配置控制的 filing。

已实现：第四个原生 Tab 及匹配的 SVG/PNG、首次入口和返回逻辑、独立的引导/同意状态、本机资料持久化、自动同步与协议守卫、协议内容配置、备案展示入口。保持题库 ID、分组顺序、答题事件和既有历史数据不变。

Validation: L3，因为涉及首次启动与同步授权守卫。最低相关验收：

- 首次同意、拒绝、离线、阅读协议返回、下次启动、老用户无同意记录和协议更新。
- 未同意时不登录、不请求；一次同意后自动上传，新作答自动调度，失败可恢复；旧版明确停止状态不被静默覆盖。
- 资料选择取消、拒绝授权、空白昵称、持久化失败、重启后保留及删除恢复默认。
- 数据清空保留学习进度，云端不恢复已清空的旧记录；重试不重复计数。
- 四个 Tab 的手机宽度、安全区、长昵称和长备案号换行，全部入口可返回，协议可滚动阅读。
- 检查真实微信设备上的头像昵称填写和平台隐私授权，模拟器检查不能代替这一项。
- 沿用项目要求的相关 cloud-sync/storage-sync 和服务端测试；不因本方案默认做发布部署。
